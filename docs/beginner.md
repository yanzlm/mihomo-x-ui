# 小白版：一步步装好 3X-UI 和 Mihomo 面板

按顺序操作，每做完一步，看一下对应的“完成标志”。不需要先学会写配置文件。

装好以后，你家设备先连这台 VPS，再由它使用你导入的订阅节点访问国外网站。你会得到两个网页：**3X-UI 用来添加连接入口，Mihomo 用来导入订阅、选择出口节点。**

**适用：一台新装的 Debian 12 或 13 VPS。已经装过节点的服务器，请先停在这里，使用[迁移说明](deployment.md)，不要为了继续安装而删除原配置。**

## 第 1 步：准备这几样东西

| 要准备的东西 | 去哪里找 / 怎么理解 |
| --- | --- |
| VPS 的公网 IPv4 地址 | VPS 商家的服务器详情页；不是你家电脑的 IP |
| root 登录资料和 SSH 端口 | VPS 商家提供；SSH 端口通常是 22，以你的实际设置为准 |
| 一个自己的域名 | 同一个域名可以创建两个子域名，不需要买两个域名 |
| 一个出口订阅链接 | 其他节点提供的订阅，稍后填进 Mihomo |
| FinalShell 或其他 SSH 工具 | 用来连接 VPS、粘贴命令 |

本篇先按 IPv4 操作。VPS 和订阅里若有需要使用的 IPv6 地址，按[详细版](full-stack.md)补充配置。

**完成标志：上面这些资料你都能找到。没有域名时，先把域名准备好再继续。**

## 第 2 步：给两个网页设置地址

进入你的域名管理网站，找到“DNS 解析”或“解析记录”，添加两条记录：

| 类型 | 主机记录 / 名称 | 记录值 |
| --- | --- | --- |
| A | `panel` | 这台 VPS 的公网 IPv4 |
| A | `xui` | 这台 VPS 的公网 IPv4 |

假如你的域名是 `example.com`，这两个网页地址就叫 `panel.example.com` 和 `xui.example.com`。**这里的 example.com 只是举例，后面要换成你自己的域名。**

如果有“代理/CDN”开关，先关闭，使用“仅 DNS”。这两个名称先只保留指向当前 VPS 的正确记录；不要留下指向旧服务器的 A/AAAA 记录。保存后等待解析生效。

**完成标志：看到两条 A 记录，记录值都是当前 VPS 的 IP。网页此时还没安装，打不开是正常的。**

## 第 3 步：放行安装需要的端口

到 VPS 商家后台找“安全组”“防火墙”或“入站规则”，放行以下 **TCP** 端口：

| 端口 | 用途 |
| --- | --- |
| 你的实际 SSH 端口 | 保持 FinalShell 能连接 |
| `80` | 自动申请网页证书 |
| `443` | 打开两个管理网页 |
| `24443` | 你家设备连接这台 VPS 的节点入口 |

如果服务器内部也设置了防火墙，同样需要放行。新手先保留默认的 `24443`，不要改成 `443`，因为网页已经要使用 `443`。

**完成标志：这些入站规则已经保存。当前 SSH 窗口保持连接，不要关闭或修改 SSH 端口。**

## 第 4 步：用 FinalShell 登录 VPS

新建 SSH 连接，填 VPS 的 IP、实际 SSH 端口、用户名 `root`，以及商家提供的密码或密钥，然后连接。

下面的命令都在 **VPS 的终端窗口**里执行，不是在 Windows 的 PowerShell 里执行。复制代码框里的内容，粘贴后按回车；等命令执行完再继续。出现红色错误或 `failed` 时先停下来。

先执行：

```sh
apt-get update
```

执行完成后，再执行：

```sh
apt-get install -y git python3 ca-certificates
```

然后下载项目：

```sh
git clone https://github.com/yanzlm/mihomo-x-ui.git
cd mihomo-x-ui
```

**完成标志：命令执行结束，终端重新出现可以输入文字的提示符，没有报错；当前位置已进入 mihomo-x-ui 文件夹。**

## 第 5 步：只填四个值，然后安装

把下面四行中**引号里的内容**改成你自己的，再一起粘贴到终端执行。不要删引号，也不要在等号两边加空格。

```sh
PANEL_DOMAIN="panel.换成你的域名"
XUI_DOMAIN="xui.换成你的域名"
SERVER_IP="换成这台VPS的公网IPv4地址"
SSH_PORT="22"
```

前三行一定要修改。第四行填实际 SSH 端口，如果不是 `22` 也要修改。**这个窗口先不要关，后面的命令会用到刚填好的四个值。**

先检查域名有没有指向正确的 VPS：

```sh
getent ahostsv4 "$PANEL_DOMAIN"
getent ahostsv4 "$XUI_DOMAIN"
```

输出左边的 IP 应该是这台 VPS 的公网 IPv4。如果没有结果或 IP 不对，回到第 2 步检查，先不要安装。

接着预览安装信息，整段复制即可，不用再改里面的文字：

```sh
python3 stack.py --panel-domain "$PANEL_DOMAIN" --xui-domain "$XUI_DOMAIN" --server-ip "$SERVER_IP" --ssh-port "$SSH_PORT"
```

看到 `plan-only; no changes` 表示只是预览。检查输出的两个网页域名有没有填错，没问题再执行：

```sh
python3 stack.py --panel-domain "$PANEL_DOMAIN" --xui-domain "$XUI_DOMAIN" --server-ip "$SERVER_IP" --ssh-port "$SSH_PORT" --apply
```

这一步会下载软件、安装服务、申请网页证书，需要等待。过程中保持 FinalShell 连接。

**完成标志：最后出现 `Services and HTTPS verified`。这表示两个网页已安装好；还需要做后面的订阅和节点设置。**

如果提示已有安装，或者安装中断，不要不断重复运行，也不要删除目录强行继续。先看文末的排错表。

## 第 6 步：取出两个网页的登录资料

安装成功后执行：

```sh
cat /etc/mihomo-x-ui/credentials.json
```

你会看到几个英文名称，按下面对应使用：

| 名称 | 是什么 / 填在哪里 |
| --- | --- |
| `mihomo_url` | Mihomo 网页地址，用浏览器打开 |
| `mihomo_secret` | Mihomo 的连接密钥，网页要求“密钥 / Secret”时填这个 |
| `xui_url` | 3X-UI 的完整登录网址，整段复制打开 |
| `xui_username` | 3X-UI 用户名 |
| `xui_password` | 3X-UI 密码 |

`xui_url` 后面那段很长的路径也是网址的一部分，不能删掉。把这些资料保存在自己的密码管理器里，不要公开发送或上传 GitHub。

**完成标志：两个网页都能打开，浏览器没有证书警告，3X-UI 能用给出的用户名和密码登录。**

## 第 7 步：先在 Mihomo 添加出口订阅

1. 打开 `mihomo_url`，按网页提示连接；如果要填服务器地址，就填同一个 `mihomo_url`，密钥填 `mihomo_secret`。
2. 找左侧“订阅管理”。也可以在 `mihomo_url` 后加 `/subscriptions/`，直接打开订阅管理页面。
3. 点击“添加订阅”。名称随便取，例如“出口订阅”；链接填你准备好的**其他出口节点的订阅**。
4. 点击“导入并应用”，等待出现节点名称。
5. 点击“返回节点面板”，找到 `PROXY`，点选一个你要使用的节点。

**不要停留在 `REJECT`。它的意思是“拒绝连接”，刚装好时默认选它，导入后需要你自己选节点。**

两种链接不要填反：

| 链接来自哪里 | 用在哪里 |
| --- | --- |
| 其他出口服务器 / 节点服务商提供的订阅 | 填进 Mihomo 的“添加订阅” |
| 稍后在本机 3X-UI 里生成的节点链接 | 导入你家电脑或手机的代理客户端 |

**完成标志：订阅页面能看到节点，PROXY 已选中一个具体节点。不要把本机 3X-UI 生成的入口再导入本机 Mihomo，否则可能接回自己。**

## 第 8 步：在 3X-UI 添加给家里连接的节点

用 `xui_url` 打开 3X-UI，进入“入站列表”，点击“添加入站”。界面中有些名称可能显示英文，按下面填写：

| 界面里的项目 | 怎么填 |
| --- | --- |
| 备注 / 名称 | 自己起名，例如“家用入口” |
| 协议 | `VLESS` |
| 监听 IP | 通常留空 |
| 端口 | `24443` |
| UUID / 客户端 ID | 点击生成，保留生成的值 |
| Flow | 选择 `xtls-rprx-vision` |
| 传输 / Network | 选择 `RAW` 或 `TCP`，以界面提供的名称为准 |
| 安全 / Security | 选择 `REALITY` |
| Target / Dest | 先测试下方示例域名；测试正常后填 `addons.mozilla.org:443` |
| Server Names / SNI | 与上面对应，填 `addons.mozilla.org` |
| X25519 密钥 | 用面板的生成按钮生成；不要自己随便填写 |
| Short IDs | 用面板的生成按钮生成 |
| Fingerprint（如有） | 选择 `chrome` |

示例域名不保证每条线路都能访问。保存前，在 FinalShell 复制执行这个测试：

```sh
openssl s_client -connect addons.mozilla.org:443 -servername addons.mozilla.org -tls1_3 -verify_return_error </dev/null
```

看到 `TLSv1.3`，并且证书验证显示 `Verification: OK` 或 `Verify return code: 0 (ok)`，再使用该示例。超时或验证失败时先停下，按[详细版的目标站检查](full-stack.md#4-在-3x-ui-创建-reality-入站)换一个可用目标，Target 和 SNI 要一起对应修改。

其余没有提到的设置先保持默认，保存入站。管理员密码和两步验证可以在面板的账户设置中自行管理；开启两步验证时保存好恢复资料。

**完成标志：入站列表里出现“家用入口”，显示已启用，端口是 24443。先别急着测试客户端，下一步还要把入口接到 Mihomo。**

## 第 9 步：让 3X-UI 使用 Mihomo 里选好的节点

在 3X-UI 找到“Xray 设置”，然后进入“出站 / Outbounds”，新增一条：

| 项目 | 填写内容 |
| --- | --- |
| 协议 | `SOCKS` |
| 标签 / Tag | `mihomo-relay` |
| 服务器地址 | `127.0.0.1` |
| 端口 | `17891` |
| 用户名、密码 | 留空 |

保存后，再进入“路由规则 / Routing”，新增一条：

| 项目 | 怎么选 |
| --- | --- |
| 入站标签 / Inbound Tag | 选择刚刚创建的 24443 入站，常见名称是 `inbound-24443`，以面板实际标签为准 |
| 出站标签 / Outbound Tag | 选择 `mihomo-relay` |
| 域名、IP、端口等其他匹配条件 | 本条都留空，只按入站匹配 |

保留面板原有的内部 API 规则。在处理这个入站的规则中，把新规则放到其他可能抢先匹配的规则前面。保存并应用；界面提示重启核心时，按提示操作。

**完成标志：出站列表有 mihomo-relay，路由规则里能看到“刚建的入站 → mihomo-relay”，应用时没有报错。**

如果你的版本只能编辑 JSON，或找不到对应选项，先看[详细版的两段示例](full-stack.md#5-让该入站通过-mihomo-出站)，不要把示例片段当成整份配置覆盖进去。

## 第 10 步：家里的设备连接并测试

1. 回到 3X-UI 入站列表，找到“家用入口”，复制它生成的节点链接或二维码。
2. 在电脑 / 手机的代理客户端中使用“从剪贴板导入”或“扫码导入”。
3. 选择刚导入的节点并连接，打开你常用的国外网站或视频。
4. 打开 IP 查询网站，核对出口是不是 Mihomo 里选择的那个节点。

**完成标志：国外网站可用，出口与所选节点一致；再检查国内网站和家中局域网设备也能正常访问。**

家中局域网和国内直连规则要在本地客户端或旁路由继续保留。这篇教程只安装服务器，不会自动修改你家的网关、DNS 或 IPv6 设置，也不能单凭网页能打开就判断 DNS 没有泄漏。

以后更换出口，主要在 Mihomo 网页里选节点；更新订阅，在“订阅管理”里点“更新”。家里用的仍是 3X-UI 生成的入口链接，入口没变时通常不需要重新导入。

## 卡在哪一步，就先看这里

| 看到的情况 | 先检查什么 |
| --- | --- |
| 域名查不到 IP / 两个网页打不开 | 第 2 步的两条 A 记录是否正确，是否关闭代理/CDN；80、443 是否放行 |
| 提示 `Existing installation detected` | 检测到了已有文件。先保留现状，确认是旧节点还是上次未完成的安装，不要直接删目录 |
| 下载、校验或证书申请失败 | 保留报错，查看下方日志。先解决失败原因；安装器不会自动清理后重装 |
| 3X-UI 网址提示 404 | 是否复制了完整 xui_url，后面的长路径是否漏掉 |
| Mihomo 连不上 / 提示密钥错误 | 地址用 mihomo_url，密钥用 mihomo_secret，不是 3X-UI 的密码 |
| 订阅导入了，仍然打不开国外网站 | PROXY 是否还选着 REJECT；第 9 步出站与路由是否保存、标签是否对应 |
| 家里连不上新节点 | 检查 24443 是否放行、入站是否启用、REALITY 目标测试是否通过，客户端是否用的是本机入口链接 |
| 能上网，但出口还是这台 VPS | 检查第 9 步：入站标签是否正确，是否被前面的其他路由规则抢先匹配 |

安装出错时，可以查看最后一段日志：

```sh
tail -n 40 /etc/mihomo-x-ui/install.log
```

找人协助时说明“卡在第几步”和具体报错。截图、日志先遮住密码、密钥和完整订阅链接，**不要发送 credentials.json 的完整内容**。

需要了解端口、迁移或更详细的检查方式，再看[详细部署教程](full-stack.md)。当前组合安装已做组件兼容检查，完整的新 VPS 安装仍需在你的实际环境验收。
